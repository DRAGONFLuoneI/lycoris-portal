# Lycoris — информационный портал

Готовый мультистраничный сайт по ТЗ «Концепция и техническое задание информационного портала Lycoris»: чистый HTML/CSS/JS без сборщиков и фреймворков — открывается прямо в браузере, редактируется в VS Code.

## Быстрый старт

1. Откройте папку `lycoris-portal` в VS Code.
2. Дважды кликните `index.html`, чтобы открыть сайт в браузере — сервер не нужен, всё работает через `file://`.
3. Для удобной разработки с автообновлением поставьте расширение **Live Server** в VS Code и нажмите «Go Live» — так корректно подтянутся все относительные пути.

## Роли и доступ

| Роль | Как получить | Что доступно |

| Гость | — | Все информационные разделы, фильтр, калькулятор, карта, отправка заявки |
| Садовод | Регистрация | Права гостя + избранные сорта, история заявок, настройки профиля |

## Как устроено хранение данных

Весь обмен данными идёт через модуль `js/db.js` — это слой доступа к данным,
повторяющий структуру реляционной БД из `database/schema.sql`: те же сущности,
те же поля, те же связи по внешним ключам. Физически записи хранятся в
`localStorage` браузера под ключом `LYCORIS_DB`.

Методы модуля повторяют операции SQL:

| Метод | Аналог в SQL |
|---|---|
| `Users.all()`, `Users.findByEmail()` | `SELECT` |
| `Users.create()`, `Leads.create()` | `INSERT` |
| `Users.update()`, `Leads.setStatus()` | `UPDATE` |
| `Users.remove()`, `Leads.remove()` | `DELETE` |

Благодаря этому переход на серверную СУБД не затрагивает интерфейс — заменяются
только тела методов (обращение к `localStorage` на `fetch()` к API).

**Пароли** никогда не хранятся в открытом виде: при регистрации вычисляется
необратимый хеш SHA-256 через Web Crypto API, сохраняется только он.
**Сессия** лежит в `sessionStorage` и завершается при закрытии вкладки.

> **Ограничения клиентского хранилища.** Данные живут в одном браузере одного
> устройства, доступны для правки через инструменты разработчика и не
> разделяются между пользователями. Это прототип уровня представления;
> эталонная схема данных вынесена в SQL-скрипт.

Все файлы прокомментированы на русском языке прямо в коде — рядом с каждым нетривиальным блоком объяснено, что он делает и почему.

## Что нужно подключить перед запуском в продакшн

Сайт полностью рабочий «из коробки» на демо-данных. Для реального проекта нужно подключить три внешних сервиса — везде оставлены явные плейсхолдеры и комментарии в коде:

### 1. Яндекс.Карты (страница `map.html`)
1. Получите API-ключ: https://developer.tech.yandex.ru/services/
2. В `map.html` замените `YOUR_YANDEX_MAPS_API_KEY` в теге `<script src="https://api-maps.yandex.ru/2.1/?apikey=...">`.
3. Логика подключения уже готова в `js/map.js` — как только `ymaps` доступен, скрипт сам строит карту с маркерами питомников вместо запасного списка.

### 2. Cloudflare Turnstile — защита формы от спама (страница `contact.html`)
1. Зарегистрируйте сайт: https://dash.cloudflare.com/?to=/:account/turnstile
2. Замените `YOUR_TURNSTILE_SITE_KEY` в атрибуте `data-sitekey` виджета `<div class="cf-turnstile">`.
3. На сервере проверяйте токен из поля `cf-turnstile-response` через Turnstile Siteverify API перед сохранением заявки.

### 3. Приём заявок на сервере (формы на всех страницах, логика в `js/form.js`)
Сейчас отправка данных **имитируется на фронтенде** (задержка ~0.9 c + окно успеха) — это сделано специально, чтобы дизайн и анимации можно было оценить без готового бэкенда.

Чтобы подключить реальный приём заявок, замените функцию `sendLeadToServer()` в `js/form.js`:

```js
function sendLeadToServer(payload) {
  return fetch("/api/leads", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  }).then((res) => {
    if (!res.ok) throw new Error("Ошибка сервера");
    return res.json();
  });
}
```

Согласно п.6 ТЗ, обработчик на сервере должен при получении заявки:
1. Сохранить её в базу данных (для выгрузки в Excel/Google Таблицы);
2. Отправить письмо администратору сайта;
3. Отправить мгновенное уведомление в рабочий Telegram-чат через Telegram Bot API:
   `POST https://api.telegram.org/bot<ТОКЕН>/sendMessage`.

## Изображения сортов

Каждая карточка сорта в «Энциклопедии» (`catalog.html`) устроена так:

1. **Если у сорта указано поле `photo`** (см. `js/data.js`) — показывается настоящая фотография с Wikimedia Commons, размещённая там на открытой лицензии (Creative Commons BY‑SA или общественное достояние). Ссылка ведёт на файл через стабильный сервис `Special:FilePath`, официально предназначенный Wikimedia именно для прямого встраивания изображений на сторонние сайты. Под фото — плашка с указанием источника и лицензии (кликабельна, ведёт на страницу файла с полной информацией об авторе).
2. **Если фото не найдено или не загрузилось** (например, нет интернета, файл переименовали или переехал) — автоматически, без «битых» иконок, подставляется собственная детализированная векторная иллюстрация цветка (`flowerIllustration()` в `js/catalog.js`): 6 отогнутых назад лепестков с прожилками и градиентом от горла к кончику + длинные изогнутые тычинки с пыльниками — точно повторяет реальное строение цветка ликориса.

Реальные фото на сегодня подключены для: **Ликорис красный** (Lycoris radiata), **золотистый** (L. aurea), **белоснежный** (L. × albiflora) и **розовый** (L. squamigera) — для них на Wikimedia Commons нашлись чистые, однозначно определённые файлы с открытой лицензией. Для **Ликорис изящный** (L. sprengeri) и **карликовый** (L. radiata var. pumila) на момент сборки сайта не нашлось фотографии с полностью ясной лицензией на конкретно этот сорт — для них используется только качественная иллюстрация.

**Если хотите сами заменить фото** (например, на собственные, более качественные снимки):
- Проще всего — положите файл в `assets/images/` и замените `photo.src` в `js/data.js` на локальный путь (например, `"assets/images/radiata.jpg"`). Локальные файлы грузятся быстрее и не зависят от Wikimedia.
- Требования к лицензии, если берёте фото из внешних источников: используйте только изображения с лицензией Creative Commons, Public Domain или купленные на фотостоках с правом коммерческого использования — и указывайте автора там, где лицензия это требует (поля `credit` / `creditUrl` / `license` в `js/data.js` уже для этого предусмотрены).

## Фон hero-блока на главной странице

Фон hero (`index.html`) — фотография ликориса с Wikimedia Commons (общественное достояние), подключена напрямую по стабильной ссылке через `Special:FilePath` — официальный сервис Wikimedia именно для встраивания изображений на сторонние сайты.

- **Файл:** «Red spider lily (Lycoris radiata).webp», источник: https://commons.wikimedia.org/wiki/File:Red_spider_lily_(Lycoris_radiata).webp
- **Где настраивается:** `css/home.css`, правило `.hero-bg` (свойство `background-image`).
- **Кадрирование:** фотография вынесена в отдельный слой `.hero-bg`, который занимает **правые 64% экрана** — цветок на снимке расположен по центру кадра, поэтому в правой панели он и оказывается справа, а левая половина остаётся свободной под текст. Сдвинуть цветок одним лишь `background-position` на фоне во всю ширину невозможно: при `background-size: cover` запаса по ширине почти нет, и цветок остаётся посередине, под текстом. Если захотите изменить пропорцию — правьте `width: 64%` в `.hero-bg`.
- **Притемнение:** `.hero::before` — градиент, в котором фото плавно растворяется в тёмном фоне слева (там, где текст), плюс `.hero::after` — лёгкое общее притемнение всего кадра.
- **Мягкий левый край:** сама фотография не обрезается встык (иначе на границе видна вертикальная полоса), а растворяется через `mask-image` в правиле `.hero-bg`. Фотография при этом лежит во вложенном `.hero-bg::before` — так анимация увеличения не тянет за собой маску. На узких экранах маска отключается: там фото занимает всю ширину.
- **Анимация:** фон плавно уменьшается с лёгкого увеличения при загрузке страницы (эффект Кен-Бёрнса, `@keyframes hero-bg-zoom`) — придаёт более кинематографичный, «грандиозный» первый экран.

**Если хотите заменить фото на своё:** проще всего — положить файл в `assets/images/hero.jpg` и заменить URL в `background-image` на локальный путь. Требования к лицензии — как в разделе «Изображения сортов» выше.

## Логотип и favicon

Значок сайта (в шапке, подвале и вкладке браузера) — стилизованная «звезда» ликориса: 6 лепестков-дуг и 6 длинных тычинок, повторяющая силуэт настоящего цветка. Разметка — в каждом HTML-файле, класс `.logo-mark` (значок в шапке/подвале) и `assets/favicon.svg` (иконка вкладки браузера, тот же рисунок на тёмном круглом фоне). Чтобы изменить цвет значка в шапке — правьте `color` в правиле `.logo` в `css/base.css`; чтобы поменять сам рисунок — правьте пути `<path>` одновременно во всех HTML-файлах и в `assets/favicon.svg`.

## Визуальные акценты («сияния»)

По всему сайту намеренно используется всего **пять** мягких свечений — по одному на смысловой акцент, чтобы они работали как подсказка взгляду, а не как украшение:

1. **Основная кнопка** (`.btn-primary` в `css/base.css`) — едва заметный тёплый ореол, усиливается при наведении. Главное действие читается первым на любой странице.
2. **Промо-баннер** (`.promo-banner::before` в `css/components.css`) — свечение из-за левого края тёмного блока на светлых страницах.
3. **Блок предзаказа** на главной (`#lead-block::before` в `css/home.css`).
4. **Шапка каталога** (`body.theme-dark .page-hero::before` в `css/catalog.css`) — чтобы верх тёмной страницы не выглядел плоским.
5. **Активный месяц** в календаре (`.cal-month.is-active` в `css/calendar.css`) — единственное свечение-состояние, показывает текущий выбор.

Все пять — полупрозрачные радиальные градиенты на акцентном цвете. Чтобы убрать или усилить любое, правьте значение `rgba(230, 0, 0, …)` в соответствующем правиле.

## Данные сортов и питомников

Все сорта ликориса и питомники-партнёры лежат в одном файле `js/data.js` — простые JS-объекты. В реальном проекте этот файл можно заменить на `fetch()`-запрос к CMS/API, сохранив ту же структуру объектов — остальной код (фильтры, карта, карточки) менять не придётся.

## Дизайн-система

Все цвета, шрифты и отступы вынесены в CSS-переменные в `css/variables.css` — чтобы поменять, например, акцентный цвет по всему сайту, достаточно отредактировать одно значение `--color-accent`.

- **Шрифты:** Playfair Display (заголовки) + Inter (текст) — подключены через Google Fonts.
- **Палитра:** белый / графитовый #1A1A1A / акцентный красный #E60000 — строго по ТЗ.
- **Тёмная тема** применена на `catalog.html` («Энциклопедия сортов» — контрастная галерея по ТЗ).

## Производительность и SEO

- Картинки-иллюстрации сортов и hero — векторная графика (inline SVG), не растровые файлы: не требуют конвертации в WebP и весят доли килобайта.
- Шрифты подключены с `preconnect` и `display=swap`.
- Анимации уважают `prefers-reduced-motion`.
- Open Graph и Twitter Card теги проставлены на всех страницах — **перед публикацией замените `https://lycoris-portal.ru` в них на реальный домен** (и при желании подставьте собственную картинку в `og:image`).
- Структура заголовков без «перескоков» уровней (h1 → h2 → h3), все поля форм подписаны, есть skip-link и favicon — базовая доступность и SEO закрыты.
- Перед запуском в продакшн: добавьте `sitemap.xml` и `robots.txt`, проверьте сайт в Google PageSpeed Insights (https://pagespeed.web.dev/) — цель по ТЗ: не ниже 85 баллов для мобильных.

## Юридический раздел

Текст в `privacy.html` — типовой черновик. Перед публикацией его должен проверить юрист с учётом реальных данных компании. Готовый генератор политики для основы: Tilda Privacy Generator (см. п.8 ТЗ).
